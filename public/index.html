💡 Resumen Ejecutivo

Este informe documenta el diseño, desarrollo y validación de un asistente de productividad empresarial inteligente. La solución descarta la generación de texto libre y adopta la arquitectura de Function Calling con la API de Google Gemini (@google/genai) y JavaScript (Node.js) gestionado con PNPM. El sistema interpreta lenguaje natural, extrae argumentos estructurados y ejecuta localmente funciones de negocio (crear_tarea y calcular_prioridad), previniendo alucinaciones ante datos incompletos con un 100% de éxito en los casos de prueba.

1. Introducción y Propósito del Laboratorio

La integración de Modelos de Lenguaje de Gran Escala (LLM) en procesos corporativos exige conectar tres conceptos esenciales:

  • Modelo de Lenguaje (Google Gemini): Analiza la semántica e intención del usuario sin ejecutar código directamente.
  • Function Calling (Contrato JSON): El modelo selecciona la herramienta adecuada del catálogo formal y genera los argumentos tipados necesarios.
  • Scripting en JavaScript (Ejecución Local): La aplicación anfitriona en Node.js valida tipos, evalúa reglas de negocio y produce el resultado estructurado de manera determinista.

3. Implementación Técnica en JavaScript

Se implementaron funciones locales en src/tools/productivityTools.js:

// Función local de negocio
export function crear_tarea({ titulo, fecha, hora, participantes, prioridad = "normal" }) {
  if (!titulo || !fecha || !hora) throw new Error("Parámetros obligatorios ausentes.");
  return {
    id: `task_${Date.now()}_${Math.random().toString(36).substring(2, 7)}`,
    titulo: titulo.trim(),
    fecha: fecha.trim(),
    hora: hora.trim(),
    participantes: Array.isArray(participantes) ? participantes : [participantes],
    prioridad: prioridad.toLowerCase(),
    estado: "pendiente",
    creada_en: new Date().toISOString()
  };
}

Para el Reto Adicional de la guía, se incorporó la función de evaluación de matriz de riesgo técnico:

// Reto Adicional: Cálculo de prioridad según impacto y urgencia
export function calcular_prioridad({ impacto, urgencia }) {
  const imp = (impacto || "").toLowerCase();
  const urg = (urgencia || "").toLowerCase();
  let prioridadCalculada = "normal";
  if ((imp === "alto" || imp === "alta") && (urg === "alta" || urg === "alto")) {
    prioridadCalculada = "alta";
  } else if (imp === "bajo" && urg === "baja") {
    prioridadCalculada = "baja";
  }
  return { impacto: imp, urgencia: urg, prioridad_calculada: prioridadCalculada };
}

5. Cuestionario de Evaluación Teórico-Práctica

¿Cuál es la diferencia entre pedirle al LLM que genere una respuesta y utilizar Function Calling?

La generación libre de texto produce lenguaje probabilístico no estructurado propenso a deformaciones sintácticas y sin conexión al mundo real. Function Calling transforma al modelo en un extractor semántico tipado, reservando la ejecución real de operaciones y validaciones de negocio al código en JavaScript.

¿Por qué no debemos permitir que el modelo ejecute cualquier función del computador?

Vulnera el principio de mínimo privilegio. Ataques de inyección indirecta de prompts podrían inducir al modelo a ejecutar comandos de sistema destructivos o robar credenciales del entorno. La aplicación debe mantener una lista blanca estricta de funciones autorizadas.

¿Qué sucede si el estudiante le proporciona al modelo una solicitud ambigua?

En sistemas sin diseño defensivo, el modelo alucina inventando datos faltantes. Con las directivas implementadas en este proyecto, el modelo suspende la llamada a herramientas y solicita aclaraciones al usuario en lenguaje natural.

¿Cómo convertirías este laboratorio en una solución empresarial real?

Evolucionando hacia una arquitectura de microservicios con API Gateway, autenticación OAuth2, colas de mensajería (BullMQ/RabbitMQ), conectores a Google Calendar, bases de datos PostgreSQL para auditoría inmutable y confirmación humana (Human-in-the-Loop) para tareas críticas.
